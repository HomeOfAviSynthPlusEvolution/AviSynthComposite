# AviSynth — Composite

[English](README.md) | [简体中文](README.zh-CN.md) | **日本語**

AviSynth — Composite は AviSynthMinus の独立した画像ブレンド・合成モジュールです。AviSynth なしでビルドでき、Merge、Overlay、Layer と関連するチャンネル・マスク操作のカーネルを提供します。通常の C 実装を備え、Google Highway によるクロスプラットフォーム SIMD を使用します。

公開インターフェースは C の型と関数を使用し、実装は C++17 です。AviSynth SDK、AvsCore、AvsSimd には依存しません。

## 画像合成を分離する理由

計算カーネルをフレームサーバーから分離することで、インターフェース、数値動作、テスト、性能を独立して保守できます。本モジュールは AviSynthMinus とともに発展し、版を固定した Git サブモジュールとして組み込み、静的リンクできます。

ホストはクリップ、スクリプト登録、フレーム割り当て、プロパティ、色空間の解釈、スケジューリングを担当します。本ライブラリは明示的なチャンネルビュー、マスク、ガイド、行範囲を扱います。ホストのフィルターを構成する部品を提供し、ホストへの統合は別途保守します。

## 対応する操作

| 分野 | 機能 |
|---|---|
| 平面ブレンド | 混合、加減算、積、反転した対象との混合、ガイド付き乗算、明暗選択、バイアス付き差分。 |
| YUV 連動処理 | 全解像度の Add、Subtract、Soft Light、Hard Light、Difference、Exclusion、Multiply、および整数の範囲超過時の彩度低減。F32 は Add、Subtract、Multiply に対応。 |
| マスク・ガイドのサンプリング | 444、422、420、411、中央・MPEG2・左上配置、および符号付きサンプリング位相。 |
| チャンネル操作 | コピー、塗りつぶし、アフィン変換、クランプ、RGB 輝度、カラーキー、矩形の交差。 |
| 互換処理 | 過去の Minus 整数ブレンドを独立した操作として提供。 |

格納形式は U8/8 ビット、U16/9～16 ビット、F32/32 ビットです。明示的なチャンネルビューで平面形式とステップ付きパック形式を扱います。アルファは通常のチャンネルで、重みマスクとブレンド対象は別です。Porter–Duff 式を暗黙には適用しません。整数サンプル、マスク、ガイドは宣言したビット深度の範囲内である必要があります。F32 の色は負値と HDR に対応し、F32 マスクは [0,1] の有限値に限ります。操作ごとの制限は[公開ヘッダー](include/composite)を参照してください。

数値動作はレビュー済みの C 実装と回帰テストに基づきます。対象となる整数 SIMD パスでは**呼び出しごとに最大 1 LSB** の差を許容し、一部の F32 パスでは値の大きさに応じた丸め誤差を許容します。繰り返し処理では誤差が累積する場合があります。参照演算には通常の C を選択してください。整数処理では作業ビット深度を上げると、正規化した丸め誤差を小さくできます。許容誤差、端点動作、フォールバック条件の詳細は[数値動作](NUMERICS.md)に記載しています。フィルター名が同じでも、すべての過去の実装との出力一致は保証しません。

## SIMD と CPU 制限

`CP_TARGET_C` は通常の C、`CP_TARGET_NATIVE` は利用可能なネイティブ実装を選び、必要に応じて C にフォールバックします。`cp_choose_target(allowed_bits)` はコンパイル済みで CPU が対応し、呼び出し側が許可したターゲットから選択します。`cp_get_kernels` は不変の関数テーブルを返し、利用不能または不正なターゲットの明示的な要求には null を返します。ターゲットには Highway のビット値を使用します。操作関数の直接呼び出しは通常の C を使用します。

選択は利用側のインスタンス単位で、Highway のプロセス全体のターゲット制限は変更しません。AviSynth への統合時、AvsSimd はホスト側で `SetMaxCPU` を解釈し、許可するターゲットを渡します。ホストは `SetMaxCPU("none")` を通常の C に対応付け、選択したテーブルをキャッシュする必要があります。

SIMD はステップ付きチャンネルと境界内の末尾処理を含むピクセル操作に対応し、追加のパディングは不要です。FP64 のないターゲットでは、倍精度を必要とする演算を通常の C にフォールバックします。矩形の交差はスカラーの幾何演算です。広い SIMD が常に高速とは限りません。

## ビルドと統合

CMake 3.24 以降と C++17 対応コンパイラーが必要です。インターフェースは C 互換で、STL コンテナーや Highway のベクトル型を公開しません。インターフェースは変更される可能性があり、リリース間のバイナリー互換性は保証しません。対応するヘッダーとライブラリを使用してください。

```sh
cmake -S . -B build/release -DCMAKE_BUILD_TYPE=Release -DCP_BUILD_TESTS=ON
cmake --build build/release --config Release --parallel
ctest --test-dir build/release -C Release --output-on-failure
```

テストに依存ライブラリのダウンロードは不要です。ライブラリのみのビルドには `-DCP_BUILD_TESTS=OFF` を指定します。組み込みビルドではテストが既定で無効です。`-DCP_SCALAR_ONLY=ON` は SIMD と Highway 依存を除去します。ベンチマークは `-DCP_BUILD_BENCHMARKS=ON`、対応する非 MSVC の Clang/GCC での ASan/UBSan は `-DCP_SANITIZERS=ON` で有効にします。

静的ライブラリ名は `Composite`、CMake エイリアスは `AviSynth::Composite` です。リポジトリをサブモジュールとして追加し、ターゲットに直接リンクします。

```cmake
add_subdirectory(third_party/composite)
target_link_libraries(MyHost PRIVATE AviSynth::Composite)
```

単独ビルドは同梱の Highway 1.4.0 を使用します。組み込みビルドでは互換性のある既存の `hwy` ターゲットを再利用し、Audio、Video、ホストでランタイムを共有できます。静的リンクの依存関係は CMake が伝播するため、利用側がカーネルのソースを列挙する必要はありません。対応する統合方法は共同 CMake ビルドで、インストール型のバイナリー SDK ではありません。

公開ヘッダーは [include/composite](include/composite) にあります。行ストライドは符号付きのバイト数、サンプルステップは正のバイト数です。各 API の行原点、重複、寿命の契約に従ってください。ピクセル操作はメモリーを割り当てません。依存するチャンネル操作が終わるまで元のガイドとマスクを保持してください。重ならない出力領域への独立した呼び出しは並行実行できます。

## テストと性能

独立テストは算術、互換動作、サンプリング、チャンネル操作、C/SIMD 比較、数値境界、不規則な寸法、符号付きストライド、行分割、並行実行、メモリー境界を検証します。C の利用側テストで公開インターフェースを確認します。CTest エントリーは 15 個で、内部で複数のケースとターゲットを検証します。

CI は Windows、Linux、macOS の SIMD と通常の C 構成、追加の Windows Win32 ビルド、Linux ASan/UBSan を対象とします。Linux と FreeBSD の x86-64、ARM64 でも正確性と性能を検証しています。カーネル検証はホストのフィルター統合テストを代替しません。

テスト有効時は参照比較を再現できるよう暗黙の浮動小数点演算の融合を無効にしますが、明示的な SIMD 融合演算は使用できます。ライブラリのみのビルドでは融合を許可します。結果の比較ではこの設定も記録してください。

任意のベンチマークは計測前に C と出力を比較し、最小・中央値・最大のミリ秒時間を報告します。8、10、16、32 ビット入力、連続・ステップ付きチャンネル、パック配置を対象とします。一部の上流カーネルはローカルリポジトリから抽出できます。コマンド、計測範囲、参照実装の制限は[カーネルベンチマーク](benchmarks/README.md)を参照してください。

比較では入力、配置、ビルド設定、CPU 制限、計測範囲をそろえてください。カーネル単体とフィルター全体は別の計測です。性能報告には時間とともに出力比較を含め、小さな差には適度な再確認を行ってください。
